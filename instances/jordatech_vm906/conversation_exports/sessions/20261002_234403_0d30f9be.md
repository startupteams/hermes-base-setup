# AgentifyMe Infrastructure Feature Roadmap — Next 20 AI Instruction Files (V2)

**Date:** 2026-10-03  
**Purpose:** Define the next 20 bounded AI-agent implementation plans after the October 3 Jira-to-outcome proof, using the Jira STNA-86-style structure supplied by Jordan. V2 applies the DKMS repository/deployment/training/trajectory decisions from the latest architecture review.

## Story-point scale

- **0–1:** extremely simple.
- **2–3:** straightforward, minor complexity.
- **5:** moderate complexity, bounded problem-solving.
- **8:** high complexity, significant effort / meaningful roadblocks.
- **13+:** do not schedule as one instruction file; split first.

## How to interpret the June 2026 sources

The STNSW-34/37/38/40/41/45 files and role documents are treated as **historical product and infrastructure intent**, not as current implementation truth.

They remain valuable because they describe:

- employee assistants;
- business-running/project bots;
- orchestrator bots;
- local/cloud model operation;
- 24/7 availability;
- backups and remote access;
- local inference and server infrastructure;
- GOOD/FAST model/agent metrics;
- SaaS deployment/hosting;
- product telemetry and user-feedback loops.

Old model names, provider pricing, hardware assumptions, server names, and dates must be re-verified when a roadmap item is executed.


## V2 sequencing decisions

[x] Canonical DKMS repository: `startupteams/dkms-project-framework`.

[x] DKMS deploys on a **new dedicated VM** as a **dedicated Kubernetes service**; it does not run inside ACMS.

[x] DKMS stores selected durable knowledge, lessons, and implementation trajectory rather than detailed ACMS Work statistics.

[x] ACMS and registered STEA agents may submit **Lessons Learned** to DKMS; STEA writes may occur outside Work Items through scoped MCP.

[x] Validated internal failure/recovery lessons may be automatically training-approved, with automatic-vs-human approval and human-review state preserved.

[x] Keep the first ~15 roadmap instruction files predominantly internal infrastructure/reliability/security/evaluation work. External Speed-to-Lead remains late in the sequence.
