If the current working model is not actually V4.1 Flash, run a strict V4.1 fit/runtime gate before changing production.

## 2.2 Preferred distributed topology

The first topology to test for a three-host deployment is:

```text
Pipeline parallel (PP): 3
Tensor parallel (TP):   6 per pipeline stage / host
Data parallel (DP):     1
Nodes:                  3
GPUs per node:          6
Total GPUs:             18
```

Why this is the first candidate:

- each pipeline stage remains inside one physical 6-GPU server,
- tensor-parallel collectives stay primarily inside a host,
- cross-host traffic is dominated by pipeline-stage transfers rather than a global TP18 all-reduce,
- this is a better fit for three symmetric 6-GPU servers connected by 100 Gb networking.

Do **not** assume expert parallelism improves this immediately. First obtain a stable PP3/TP6 baseline. If the installed DeepSeek/vLLM path supports expert parallelism in combination with the selected PP/TP layout on this hardware, benchmark an EP-enabled candidate afterward and keep it only if it is measurably better and equally stable.

Secondary topology only if PP3/TP6 is unsupported or broken:

```text
TP=18 / PP=1 / DP=1
```

This topology requires global cross-node collectives and should only be attempted after RDMA/NCCL has been proven clean. Do not make TP18 the default merely because it is simpler to describe.

## 2.3 CPU offload may be required

Because 18 x 20 GB = 360 GB raw VRAM, a V4.1 Flash checkpoint may require CPU offload even when quantized. If so:

- calculate the actual per-node weight requirement from the selected artifact,
- reserve VRAM for CUDA graphs/runtime/KV cache rather than treating all 20 GB/GPU as available weights,
- inventory RAM inside VM103/VM109/VM111 and on each Proxmox host,
- calculate required CPU-offload GB per node and per GPU,
- confirm the chosen vLLM build supports that offload with this model/topology,
- do not increase VM RAM until host headroom is checked,
- if VM RAM changes require a guest restart, perform one VM at a time with rollback ready.

If the only way to make the checkpoint fit would create unusably low throughput, record that benchmark result honestly rather than declaring success merely because the model loads.
