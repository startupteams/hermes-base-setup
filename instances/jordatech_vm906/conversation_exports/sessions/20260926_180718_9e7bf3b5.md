# 0. Architecture Clarification

Do not assume every Proxmox VM/LXC should have a ZFS snapshot.

There are currently two different protection mechanisms:

## Layer A - Proxmox Backup Server (PBS)

This is the intended **cluster-wide VM/LXC backup system**.

It protects guests across all 16 Proxmox nodes.

Current intended retention:

```text
keep-last    = 3
keep-daily   = 14
keep-weekly  = 8
keep-monthly = 6
keep-yearly  = 2
```

`keep-last = 3` means the three most recent successful backup snapshots.

PBS is deduplicated/incremental at the data-chunk level. Each backup appears as a complete recovery point, but unchanged chunks are reused rather than storing another complete physical copy.

PBS is the canonical answer to:

> "Can I restore this VM or LXC?"

## Layer B - ZFS filesystem snapshots on MIAM-00147

Historically MIAM-00147 also ran local ZFS snapshots:

```text
bulk -> 30 days of @auto-* snapshots
fast -> 7 days of @auto-* snapshots
```

These protect datasets physically stored on MIAM-00147.

They do not directly snapshot VM122 on MIAM-00135, VM103 on MIAM-00111, or other guest disks that live on other Proxmox nodes.

ZFS snapshots are the answer to:

> "Can I roll back this local ZFS dataset on MIAM-00147?"

Do not report a missing ZFS snapshot for a remote guest as proof that its backup is broken.

For every VM/LXC, first determine whether the expected protection mechanism is:

```text
PBS guest backup

application-specific backup
or a combination
```

Therefore retain daily recoverability without suppressing backups solely because a VM had few changes.
