# ACMS First Live Deployment Plan — MARION-IA-USA VM + Internal Web UI

**Date:** 2026-09-25  
**Repository:** `startupteams/acms-project-framework`

**Goal:** Put ACMS live on the MARION-IA-USA infrastructure with a usable internal web UI as quickly as practical.

## 1. Target outcome

Deploy a dedicated ACMS VM with:

- FastAPI ACMS backend
- PostgreSQL
- Alembic migrations
- internal HTTPS web UI
- LLDAP login
- Administrator / Worker / Observer roles
- internal-only access
- automatic restart on boot
- documented deploy, update, rollback, backup, and smoke-test procedures

This first deployment is intentionally a simple single-node internal MVP. Do not add Kubernetes, an event bus, sharding, HA PostgreSQL, or multiple ACMS replicas.

- Python 3.12+
- FastAPI
- Pydantic

- asyncpg
- PostgreSQL
- Alembic
- pytest

- HTTP+JSON/SSE as the MVP transport direction
- temporary bearer token only for machine/API authentication

## 6. Human authentication

The current bearer token is machine authentication.

**Never expose the bearer token to browser users or browser JavaScript.**

Human web login must authenticate against the existing LLDAP service.

Implement:

- username/password login against LLDAP
- no password storage
- signed server-side/session-cookie authentication
- `HttpOnly` cookies
- `Secure` cookies under HTTPS
- appropriate `SameSite` policy
- reasonable session timeout

Map LLDAP groups to:

- Administrator
- Worker
- Observer

Group names should be configurable.

Do not automatically create or modify LLDAP groups without explicit authorization.

A user who authenticates successfully but has no mapped ACMS role must be denied.

Initial UI authorization:

- Administrator: all currently implemented pages
- Worker: currently implemented read views
- Observer: read-only

Do not add privileged action buttons until the backend operation and authorization rules exist.

Humans set product intent, approve scope, approve significant decisions, define mandatory governance boundaries, and approve merges.

- **Human-Directed**

- **Source-Derived**

Human-Directed does not mean approved; it remains future scope until promoted.

## Centralized governance, decentralized execution

ACMS controls approved assignment, scope, budget, context access, permissions, and governance. It must not become the synchronous permission service for every shell command/tool call/test/retry.

- Organization
- Product
- Project
