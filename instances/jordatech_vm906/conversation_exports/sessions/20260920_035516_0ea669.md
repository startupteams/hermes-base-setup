## 2. Leading hypothesis — test this FIRST

### H1 — Hermes is sending an illegal output-token cap to vLLM, then misclassifying the vLLM 400 as a prompt/context overflow

This symptom closely matches a current Hermes/vLLM bug family:

1. Hermes believes the context window is 70K.
2. The actual conversation is only ~7–8K tokens.
3. Hermes sends a request containing an excessive `max_tokens` / output cap.
4. vLLM rejects it because `input_tokens + max_tokens` cannot fit inside `max_model_len`.
5. Hermes classifies the vLLM 400 as a context overflow.
6. Hermes unnecessarily compresses the conversation.
7. The same illegal request is retried.
8. Hermes eventually says `Cannot compress further` and resets the session.

A public Hermes issue filed in September 2026 documents this exact failure mode with **Qwen3.8-27B INT4 on self-hosted vLLM**. The characteristic backend error is:

```text
max_tokens=... cannot be greater than max_model_len=max_total_tokens=...
Please request fewer output tokens
```

Do **not** assume this is the cause until the actual MARION logs show the same or equivalent response.

### Important distinction

`context_length` and `max_tokens` are not the same setting:

- `context_length = 70000` means the total request budget: system prompt + tool schemas + history + user input + generated output.
- `max_tokens` is only the maximum generated output for one response.

For Hermes agent work, keep the total context at **70,000**. Do **not** request 70,000 output tokens per turn.
