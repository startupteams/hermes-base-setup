## 3. Important model facts and design implications

### Qwen3.6-35B-A3B

The official model supports far more than 70K natively, so **no RoPE extension or context hack is required**. Use `--max-model-len 70000` and preserve the existing quantized model.

This is an MoE model. The current MARION architecture has already successfully used DP + EP. For concurrency, prefer:

1. **TP1 / DP6 / EP6** on six GPUs.
2. If 70K KV/cache pressure makes five simultaneous long-context sessions unstable, test **TP2 / DP3 / EP6**.
3. Do not use pipeline parallelism on this single host.

The goal is not six benchmark replicas for their own sake; the goal is **five real Hermes sessions that can each enter a >=65K context without OOM or server failure**.

### Qwen3.8-27B

The official model supports 262K natively, so 70K is also safely within native context. No YaRN or RoPE scaling is required.

This is a dense model, so expert parallelism does not apply.

The preferred layout is the previously strong throughput layout:

1. **TP2 / DP3** -> three replicas across all six GPUs; target three agents.
2. If 70K KV pressure is too large, use **TP3 / DP2** -> two replicas; minimum acceptable two agents.
3. Do not use PP on this single host.
4. Do not fall back to TP4 merely because it was previously active; the previous benchmark strongly favored the multi-replica layout for agent concurrency. Use TP4 only as a diagnostic/rollback option, not the new target.

### DeepSeek-V4.1-Flash

Treat this as a **strict feasibility-gated experiment**, not an assumption.

Current public information indicates:

- DeepSeek V4.1 Flash is a very large MoE model (552B backbone plus large Engram memory).
- Current vLLM support is very new and requires a recent nightly / v0.30-era code path.
- Officially verified hardware is datacenter-class; RTX 3080 / SM86 is not a verified target.
- The combined MIAM-00143 + MIAM-00144 VRAM budget is only **240 GB total**.
- Public low-bit V4.1 artifacts are evolving rapidly; some small-looking artifacts omit or offload the large Engram tables and are not yet proven end-to-end on stock vLLM/llama.cpp.

Therefore:

- **Do not download hundreds of GB before doing a fit/runtime capability calculation.**
- Do not spend more than **60-90 minutes** on the feasibility gate unless the gate clearly passes.
- Do not destabilize the two working Qwen hosts or the SR-IOV/RDMA configuration to force this model to run.
- If local V4.1 Flash cannot be made credible within the timebox, register a provider-backed `deepseek-flash`/V4.1 endpoint in LLM Manager for Hermes testing and preserve MIAM-00143/00144's current rollback presets. Record local V4.1 as blocked by current runtime/VRAM constraints rather than pretending success.

If a supported local artifact does pass the fit gate, the preferred distributed layout is:

- **PP=2, TP=6, DP=1**, one pipeline stage per host, with expert parallel enabled within each TP group if the runtime supports that model/layout.
- This minimizes cross-node layer-by-layer collectives compared with TP12 and is naturally compatible with the requirement for two concurrent requests/microbatches.
- Fallback only if PP2 is unsupported: **TP=12, DP=1, EP enabled**, using the existing 100G path without changing host PCI/network configuration.
- Do **not** use DP2: each 6-GPU node does not have enough VRAM to hold an independent full copy of V4.1 Flash.

Initial `max-num-seqs` for DeepSeek should be 2. Increase only after the two-agent 65K acceptance test passes.
