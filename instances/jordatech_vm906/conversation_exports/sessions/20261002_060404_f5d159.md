# 4. Likely root causes, ranked

## Root cause 1 — highest confidence: STNA-88 had no pre-existing Jira link/Work

This exactly matches the code:

- Search finds ready AI-assigned STNA-88.
- `_process_observation()` cannot find a `jira_issue_links` row.
- It emits `JIRA_CANDIDATE_OBSERVED`, increments `unchanged`, and returns.
- Run finishes `completed`.
- No Work is created.

Relevant code: `acms/jira_reconcile.py:289-315`.

## Root cause 2 — split-brain linkage representation

There are two linkage representations:

1. Jira columns on `work_items`;
2. `jira_issue_links`.

Reconciliation candidate correlation uses only `jira_issue_links`:

- `acms/jira_reconcile.py:289-293`
- linked direct scans use the same table at lines 210-223.

But product bootstrap only writes fields on `WorkItemRecord`:

- `acms/product_bootstrap.py:439-449`

It does not create a `JiraIssueLinkRecord`. A bootstrap-linked issue can consequently be treated as unlinked by reconciliation.

The ordinary link endpoint correctly writes both representations:

- link row: `acms/jira_api.py:142-158`
- Work fields: lines 159-163.

Which path created/linked STNA-87 versus STNA-88 is therefore an important comparison point.

## Root cause 3 — “Startup Teams” may not be the configured immutable Jira account

Candidate JQL matches exact account ID, not display name:

- `acms/jira_client.py:155-165`.

If STNA-88’s “Startup Teams” assignee resolves to a different account ID than `ACMS_JIRA_AI_ACCOUNT_ID`, it is absent from the scan. An empty successful result still yields a `completed` run.

This cannot be confirmed without live Jira/config access, which was intentionally not performed.

## Root cause 4 — even a linked candidate is not started by reconciliation

For existing linked planned Work:

- only `added++` and `JIRA_WORK_QUEUED` happen:
  `acms/jira_reconcile.py:419-431`.

There is no assignment selection or dispatch. Therefore the UI claim that Check Jira now “starts eligible work” is not implemented by this path.

## Root cause 5 — pagination/search omission

The client assumes `total`/`startAt` pagination:

- `acms/jira_client.py:174-183`.

If the Jira endpoint returns a successful page without `total`, only the first page is scanned and the run can still be full/completed.
